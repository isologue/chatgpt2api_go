# 原型验证记录

日期：2026-11-02。环境：Windows 上开发，Docker Desktop Linux 容器运行性能测试；Go 1.27.3、PostgreSQL 16。原 Python 主服务继续独立运行。

## 验证范围

这是单实例 Go 调度和生成核心，不是原管理系统的完整重写。已实现的 HTTP 接口、上游协议与性能参数见根目录 README。

普通单元测试和 `go vet ./...` 已通过。测试覆盖准入与停机竞态、共享总预算、切号评分、账号校验 singleflight、RT 旋转持久化、取消与槽位释放、下载重试、完整图片解码、同源会话隔离、同步/异步返回协议以及重启任务恢复。

最新源码的 `go test -race ./... -count=1` 已在 Linux 容器通过，启用了 200/500/1000 模拟流、1000 完整 HTTP 与真实 PostgreSQL 负载测试，测试包耗时约 5.95 秒。Linux 竞态检查和 PostgreSQL 集成测试使用专用测试库，不触碰运行库。PostgreSQL 测试会清空测试库中的 `core_*` 表，不能使用运行数据库 URL。

## 模拟负载

模拟服务采用 loopback HTTP/SSE 和 4×4 PNG。压测账号为虚构账号，校验缓存预设新鲜，不包含 1000 个真实账号同时远程校验或 RT 续期的耗时。每轮把所有上游流阻塞在同一个 barrier，确认同时活跃数量达到目标后统一放行，再走下载、完整解码和结果处理。这里只能证明本地并发机制，不能据此推算真实图片生成耗时、带宽或真实上游配额。

| 场景 | 成功 / 失败 | 同时活跃上游流 | 全部进入流所需 | P50 | P95 | barrier 时 Go 堆 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Engine 200 并发，内存测试存储 | 200 / 0 | 200 | 160 ms | 182.7 ms | 205.6 ms | 12.4 MiB |
| Engine 500 并发，内存测试存储 | 500 / 0 | 500 | 102 ms | 150.2 ms | 175.6 ms | 26.9 MiB |
| Engine 1000 并发，内存测试存储 | 1000 / 0 | 1000 | 114 ms | 228.8 ms | 264.6 ms | 59.3 MiB |
| 完整 HTTP 1000 并发，内存测试存储 | 1000 / 0 | 1000 | 118 ms | 252.7 ms | 292.6 ms | 109.0 MiB |
| Engine 1000 并发，真实 PostgreSQL | 1000 / 0 | 1000 | 130 ms | 219.2 ms | 297.8 ms | 58.0 MiB |

完整 HTTP 测试包含 500 个同步与 500 个异步请求，混合 URL/Base64 返回、异步轮询、URL 图片读取和内容比对；所有执行槽位占满时额外 HTTP 请求返回 `429`。PostgreSQL 场景实际写入 1000 条成功日志与 500 个成功异步任务，持久化错误为零，账号槽位无泄漏。PostgreSQL 场景通过 Engine 接口提交，不能把两组结果合称为同一轮“HTTP + PostgreSQL 1000 并发”。

堆数据是该测试进程在 barrier 时的 `HeapAlloc`，含前序测试残留和 GC 波动；不是容器 RSS，也不是十万账号的内存测量。Windows 的极高并发 loopback 测试曾遇到连接拒绝，Linux 容器内完成了上述验证；不宣称 Windows 网络限制已修复。

模拟测试复现：


## 真实上游单张验证

使用一份临时 AT 账号文件，在现有线上网络环境中运行独立测试进程；没有连接原数据库调度池，没有监听新服务端口，也没有替换线上主服务。未复制或刷新 RT。调试产生的远程临时目录与图片由测试清理。

初次运行定位了两个兼容差异：

1. 动态挑战包含原 Python 解释器同样未支持的指令。旧实现会在求解失败后提交空值让上游判定，Go 最初提前退出；已对齐旧行为，并增加 `turnstile_solver_failures` 指标与动态挑战阶段耗时。
2. 图片地址返回同源 `/backend-api/estuary/content`，Go 最初把它当作无需会话的 CDN 地址，返回 HTTP 403。现仅对配置上游同源的这个内容接口复用账号会话。其他地址和跨源重定向均不携带 Authorization/Cookie；有针对性测试覆盖这条边界。

修正后的单次真实结果：

- 生成成功：1 张，文件 1,793,251 字节（约 1.71 MiB）。
- 总耗时约 16.20 秒；上游生成流 13.96 秒。
- 下载传输约 0.71 秒，完整图片解码约 0.15 秒。
- 完整下载及解码成功后发布文件，测试结束删除临时文件。

这证明当前账号与网络条件下的单张生成链路可用。真实 200/500/1000 并发、不同账号类型/套餐、长尾补查和上游协议变动仍需要独立验证。动态挑战指令支持并不完整，上游可能拒绝空值；不能保证后续每次挑战都成功。

## 后续边界

- 原型独立端口 9080，独立 PostgreSQL 与图片卷；不自动共享原号池或 RT。
- 未移植管理 UI、热冷池维护、完整额度查询、保留清理、多租户、分布式调度和幂等重试。
- 启动仍整体加载账号；十万账号内存与调度容量尚未实测。
- 日志、账号状态和任务状态目前为同步持久化，数据库故障或高延迟会影响完整响应时间；不宣称已解决持久化长尾。
- 下载并发、解码并发和响应并发独立受限。Go 不会消除上游限流或服务器带宽上限。

下一步应给原型分配独立测试账号，逐级测试真实负载，按准入、上游流、下载等待、传输、解码和数据库耗时定位容量，再决定哪些成熟组件迁回主服务。

## 本地部署核验

最终源码已通过 `docker compose up -d --build` 构建部署，`core` 与 `postgres` 均为 healthy，HTTP 绑定 `127.0.0.1:9080`。核验了健康/就绪接口、独立管理 key、模型列表、非法 n 拒绝与空号池 503。运行库未导入线上账号；真实烟测凭据与签名下载地址已从本地临时目录删除。
