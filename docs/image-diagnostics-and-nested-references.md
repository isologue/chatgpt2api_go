# JSON 图片引用兼容与生成诊断

## JSON 图片编辑

`POST /v1/images/edits` 的 JSON 请求现在同时接受字符串与嵌套对象形式的 `image_url`：

```json
{
  "model": "gpt-image-2",
  "prompt": "把衣服改成黑色",
  "images": [
    {"image_url": {"url": "https://example.com/reference.png"}},
    {"image_url": "data:image/png;base64,..."}
  ],
  "async": true,
  "response_format": "url"
}
```

同步与异步均适用；`image`、`images`、`image_url` 和遮罩沿用现有解析入口。原字符串、Base64 和混合多图形式继续兼容。嵌套对象只读取 `url`，不使用其中的 `headers` 等鉴权信息。协议、URL 账号密码、内容、体积和图片数量限制不变。空对象或非字符串 URL 仍会被拒绝。

调用日志保留调用方实际发送的请求，不将嵌套对象改写成字符串。

## 查看生成流和补查诊断

进入「日志管理 → 详情」，点击一次账号尝试的结果标签（错误码或「生成成功」），展开「生成流与补查诊断（脱敏摘要）」。旧日志没有该字段，不会回填。

每次账号尝试独立保存 `attempts[].diagnostics`：

- **上游生成流**：真实 HTTP 状态、读取字节数、事件数、无效事件数、是否取得会话/图片标识、是否收到 `[DONE]`、EOF/硬超时/取消等结束方式。
- **首尾事件**：最多开头 3 个、后续末尾 8 个事件的结构摘要，包含相对时间、角色、消息状态和内容类型，不复制事件正文。
- **结果补查**：配置预算、实际耗时、退出原因、图片标识命中来源。
- **两个补查来源分别统计**：会话接口和任务接口各自的查询次数、真实 HTTP 状态分布、失败数、收尾取消数、最近查询耗时和最近响应结构。任务摘要仅统计匹配当前会话的任务。

「成功读取次数」表示 HTTP/JSON 读取成功，不代表已经拿到图片。一个来源成功或补查结束时取消另一个在途查询，单独计入「收尾取消次数」，不计为上游失败。最近查询耗时可能属于收尾取消的请求，最近响应摘要则保留取消前最后一个真实结果，两者不一定对应同一次查询。

新增摘要不保存提示词、图片内容、URL 或令牌；已有「上游原始响应」仍沿用前 64 KiB 截断规则，不属于新增脱敏摘要。长提示词即使占满原始响应前缀，也不影响独立记录流尾部的结构信息。

诊断随既有账号尝试 JSON 持久化，不新增数据库列，不放入日志列表摘要，不返回给调用方。生成超时、补查预算、切号上限、评分规则和对外错误包装均不变。

## 本地验证范围

新增测试覆盖嵌套 URL、混合 Data URL、多图/遮罩、同步/异步、URL/Base64 返回、原始请求保留、非法 URL、长流首尾摘要、真实 HTTP 状态、补查超时/取消及切号诊断隔离。

已通过 `go test ./...`、`go vet ./...`、`go test -race ./... -count=1`，以及前端 JavaScript 语法检查。上述验证使用本地模拟上游；未调用真实上游，未部署线上。需要 `CORE_TEST_DATABASE_URL` 的数据库集成测试未配置运行环境，跳过，不等同于真实 PostgreSQL 集成验收。

## 图片工具限流识别

生成流、会话补查和匹配当前会话的任务补查均识别 `system_error` 中的 `ChatGPTAgentToolRateLimitException` 等明确限流错误。识别范围限定为工具/助手的结构化错误，不从用户回显或普通助手文本中判断账号限流。分段错误等待消息完成后再提前退出，以保留后续的恢复时间。

明确工具限流不再等待补查窗口，直接按现有切号上限换号。账号保留启用，不扣分；上游提示的 23/24 小时等恢复时间沿用现有解析规则，加一分钟余量后保存为限流截止时间，限流期间调度器排除该账号。日志保留实际工具错误内容，生成流结束原因或补查结果显示为 `upstream_rate_limited`。安全审核拒绝继续优先处理，不切号、不扣分。

补查接口的 HTTP 429 与图片工具明确失败分开处理：遇到 HTTP 429 后停止重复访问该来源，另一个来源仍可在补查预算内找回图片；两来源都限流时直接退出。如果补查窗口耗尽仍无图片，则保留已取得的限流错误，不再覆盖成普通补查超时。调用方取消或请求总预算耗尽仍按其原有规则优先退出。

补充回归测试覆盖真实工具错误形态、分段错误、超过 64 KiB 的用户回显、切号成功、限流状态持久化、调度排除、双来源 HTTP 429、单来源 429 后从另一来源成功恢复、调用方取消，以及安全审核优先级。
